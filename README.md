# CCFOLIA Character JSON Tool

一款用來建立、編輯、整理及轉換 **CCFOLIA 角色資料** 的瀏覽器工具。除了基本的角色 JSON 編輯，也提供 PNG 圖片與差分管理、差分名稱批次修改、CCFOLIA Room ZIP 匯入／匯出，以及 Google 試算表角色卡同步功能。

本工具以瀏覽器介面操作為主，不需要手動編寫 JSON。你可以匯入既有資料，也可以從連結或 JSON 開始建立角色，再依照需要整理圖片、差分及指令。

> 本文件以目前專案內的程式功能為準。不同版本的介面或功能可能略有差異；若畫面與本文描述不一致，請以實際使用版本為準。

## 使用方法（建議先閱讀）

第一次使用時，建議先依照以下流程操作。工具支援匯入既有資料，也能從新資料開始建立角色；請依手上資料的形式選擇方式。

### A. 匯入既有角色資料：推薦順序

工具有三種主要匯入方式，建議依照以下順序選擇。越前面的方式越推薦：

1. **CCFOLIA Room ZIP（最推薦）**：如果手上有完整的 Room ZIP，優先使用頁面上方的「匯入 ZIP」。ZIP 通常能一併帶入角色資料及相關圖片，較適合完整還原與接續編輯。
2. **連結（次推薦）**：如果角色資料是透過 Google 試算表管理，將試算表共用連結貼到「外部連結」欄位，讓工具讀取並同步角色卡資料。請確認試算表的讀取權限及預設「人物卡」分頁。
3. **角色 JSON**：如果只有 CCFOLIA Character JSON，使用頁面上方的「匯入 JSON」，將完整 JSON 貼入視窗後匯入。這種方式適合手上只有 JSON 文字或 `.json` 檔內容的情況；圖片若未包含可讀取的圖片資料，可能需要另外選取圖片。

**怎麼選？** 有 Room ZIP 就先用 ZIP；使用 Google 試算表管理資料就用連結；只有角色 JSON 時再使用 JSON 匯入。

### B. 新建立角色：推薦流程

如果不是要還原既有 Room，而是要建立一份新的角色資料，建議優先使用連結方式取得／同步角色卡資料，其次再使用 JSON。完成資料載入後，依照以下順序整理圖片與指令：

1. **先貼上連結**：將 Google 試算表共用連結貼到「外部連結」欄位。確認工具能讀取到角色資料；若沒有使用試算表，則可改用 JSON 匯入或直接填寫表單。
2. **選擇差分圖片**：先新增或匯入需要的差分圖片，確認每張圖片都有正確的差分名稱。若已有差分 ZIP，可使用差分區的「匯入 ZIP」；也可以直接選取一張或多張 PNG。
3. **選擇主圖片**：差分圖片整理完成後，再設定角色主圖片。若主圖片本身也在差分圖片之中，可使用「從差分選擇主圖片」，避免重複選取檔案；也可以直接選擇 PNG 作為主圖片。
4. **複製差分名稱到常用指令**：按下「複製差分名稱」，將整理好的差分名稱複製後，貼到「常用指令」欄位中，再依照 CCFOLIA 使用習慣調整指令內容。這樣可以讓差分名稱與角色指令保持一致。
5. **檢查並匯出**：確認角色名稱、屬性、圖片預覽、差分名稱及常用指令，再選擇「複製 CCFOLIA JSON」、「下載 JSON」或「下載 CCFOLIA Room ZIP」。

> **小提醒：** 建議先處理差分圖片、再設定主圖片，最後才複製差分名稱到常用指令。這樣可以避免圖片尚未整理完成，就先把不完整或之後會更動的名稱貼進指令欄位。

### C. 最短操作流程

| 你的情況 | 建議操作 |
|---|---|
| 手上有完整 CCFOLIA Room ZIP | 匯入 ZIP → 檢查角色與圖片 → 修改 → 匯出 |
| 使用 Google 試算表管理角色卡 | 貼上試算表連結 → 等待讀取／同步 → 整理差分與主圖片 → 複製差分名稱到指令 → 匯出 |
| 手上只有角色 JSON | 匯入 JSON → 補齊或確認圖片 → 整理差分與指令 → 匯出 |
| 從空白開始建立 | 填寫基本資料 → 加入差分圖片 → 設定主圖片 → 編輯指令 → 匯出 |

## 一、工具簡介

本工具主要提供以下用途：

| 功能 | 說明 |
|---|---|
| 建立角色資料 | 透過表單輸入角色名稱、屬性、圖片、指令及其他設定，自動產生 CCFOLIA Character JSON。 |
| 編輯既有角色 | 匯入角色 JSON 或 Room ZIP，將資料載入表單後繼續編輯。 |
| 管理角色圖片 | 使用 PNG 作為主圖片與差分圖片，提供預覽及圖片雜湊命名。 |
| 管理差分名稱 | 新增、刪除、複製差分名稱，或使用批次修改工具統一命名。 |
| 同步 Google 試算表 | 讀取試算表中的角色 JSON，定期檢查變更，並讓使用者選擇要更新的欄位。 |
| 匯出角色 JSON | 複製 JSON 內容或下載 `.json` 檔案。 |
| 建立 Room ZIP | 將角色資料及相關圖片打包成 CCFOLIA Room ZIP。 |
| 匯入 Room ZIP | 讀取 Room ZIP 中的角色資料及圖片，還原至編輯介面。 |

### 適合哪些使用情境？

- 想快速建立 CCFOLIA 角色卡，不想直接編輯 JSON。
- 已經有角色 JSON，想修改屬性、指令或圖片。
- 有大量表情差分，需要快速整理圖片及名稱。
- 希望透過 Google 試算表管理角色卡資料，並在資料更新時選擇性同步。
- 想將角色資料與圖片一起打包，方便備份或轉移。

## 二、快速開始

完整的推薦操作順序已整理在文件最前面的[使用方法](#使用方法建議先閱讀)。這一節補充第一次開啟工具時的基本操作：

1. 開啟工具網頁；若使用下載的專案，請保留 HTML、JavaScript、CSS 及相關資料夾的原始相對位置。
2. 依照手上的資料選擇匯入方式：優先使用 Room ZIP，其次使用 Google 試算表連結，最後使用角色 JSON。
3. 若是新建立角色，先貼上連結（如有），再整理差分圖片、設定主圖片，最後將差分名稱複製到常用指令。
4. 檢查表單及頁面下方的「最終 JSON」內容。
5. 選擇複製 JSON、下載 JSON 或建立 Room ZIP，保存完成後再離開頁面。

工具的詳細欄位說明及各功能操作，請接著閱讀下方「完整功能介紹」。

## 三、完整功能介紹

### 1. 基本資料

基本資料區用來設定角色最主要的識別資訊。

| 欄位 | 用途 |
|---|---|
| 角色名稱 `name` | 角色顯示名稱。 |
| 備註 `memo` | 角色備註內容，可放置補充資訊。 |
| 行動值 `initiative` | 角色的行動值。 |
| 外部連結 `externalUrl` | 可填入相關網址；Google 試算表同步功能也會使用此欄位讀取試算表連結。 |

**外部連結與試算表同步：** 若要使用 Google 試算表同步，請在此欄位貼上 Google 試算表的共用連結。相關設定及限制請參考[Google 試算表同步](#11-google-試算表同步)。

### 2. 變動屬性 Status

變動屬性適合用來記錄遊戲中會變化的數值，例如 HP、MP、SAN 或其他自訂數值。

每筆變動屬性包含：

- **名稱 `label`：** 屬性名稱，例如 `HP`。
- **目前值 `value`：** 目前數值。
- **上限 `max`：** 屬性最大值。

操作方式：

1. 按下「新增變動屬性」。
2. 填入名稱、目前值及上限。
3. 若不需要某一筆資料，按該筆右側的「刪除」。

可以依照角色系統自行增加多筆自訂屬性。變動屬性會寫入 JSON 的 `status` 陣列。

### 3. 固定屬性 Params

固定屬性適合放置角色的固定數值或檢定補正，例如 DB、技能補正或其他自訂欄位。

每筆固定屬性包含：

- **名稱 `label`：** 欄位名稱，例如 `DB`。
- **內容 `value`：** 欄位對應的數值或文字，例如 `+1D6`。

操作方式：

1. 按下「新增固定屬性」。
2. 輸入欄位名稱及內容。
3. 不需要的項目可按「刪除」。

固定屬性會寫入 JSON 的 `params` 陣列。與變動屬性不同，固定屬性沒有目前值／最大值的欄位組合。

### 4. 角色圖片與差分

本區負責設定角色主圖片及表情／姿勢差分。圖片格式使用 **PNG**。

#### 4-1. 主圖片

按下「選擇圖片」即可選取 PNG 檔案。選取後，工具會處理圖片資料、計算 SHA-256、顯示圖片預覽，並將對應圖片資訊寫入角色資料。

如果已經先加入差分圖片，可以使用「從差分選擇主圖片」的選擇介面，直接從已載入的差分圖片中挑選主圖片，不必再次選取同一張檔案。

設定中的「自動從差分帶入主圖片」可控制選擇主圖片時是否優先使用已載入的差分圖片。若不希望從差分選擇，可關閉此選項，改為直接選取 PNG 檔案。

#### 4-2. 新增差分

1. 按下「新增差分」。
2. 在差分名稱欄位輸入名稱，例如 `@笑`、`@生氣`。
3. 按下該筆的「選擇圖片」，選取 PNG。
4. 確認圖片預覽及差分名稱。
5. 重複以上步驟，加入其他差分。

每筆差分都有自己的名稱與圖片。若要移除差分，按下該筆的「刪除」。

#### 4-3. 一次選取多張差分圖片

差分圖片選擇器支援一次選取多張 PNG。選取多張圖片後，工具會逐張建立差分項目：第一張圖片會套用到目前選擇的差分列，其餘圖片會新增為獨立差分列。

使用前請留意：

- 請確認選取的檔案都是 PNG。
- 多張圖片會建立多筆差分，請在匯入後檢查名稱是否符合需求。
- 若啟用了自動帶入圖片名稱，工具會依照目前設定協助填入名稱；仍建議逐筆確認。

#### 4-4. 複製差分名稱

按下「複製差分名稱」可將目前差分名稱整理成文字並複製，方便貼到其他地方備份、整理或編輯。

#### 4-5. 匯入差分 ZIP

差分區提供獨立的「匯入 ZIP」功能，可讀取符合工具預期結構的差分圖片 ZIP。此功能與 CCFOLIA Room ZIP 不同：

- **差分 ZIP：** 用來匯入一組差分圖片及其清單資料。
- **Room ZIP：** 用來匯入完整 Room 資料及角色。

差分 ZIP 會讀取其中的 `sprite-namer.json` 清單，並依照清單所記錄的路徑、圖片資訊及差分群組處理圖片。若 ZIP 缺少必要清單或格式不符合預期，可能無法正確匯入。

### 5. 差分名稱批次修改

若差分數量很多，或圖片名稱包含重複前綴、編號等內容，可以使用差分區旁的「修改名稱」功能批次處理。

這項功能只修改差分名稱欄位，不會重新命名或替換圖片本身。

#### 5-1. 搜尋與取代

- **搜尋內容：** 輸入想要尋找的文字或規則。
- **取代為：** 輸入符合條件的名稱替代內容。
- **預覽：** 依照目前條件產生修改結果，檢查修改前後的名稱。
- **儲存：** 確認預覽無誤後，將結果套用至差分名稱欄位。
- **取消：** 放棄本次修改，不套用變更。

建議先按「預覽」，確認每一筆名稱都符合預期，再按「儲存」。

#### 5-2. 智慧偵測共同前綴

按下「智慧偵測共同前綴」，工具會分析目前差分名稱，嘗試找出名稱中重複的前綴或編號格式，並協助填入搜尋及取代規則。

例如，當多筆差分名稱具有相同角色名稱、數字編號或底線格式時，可以先使用智慧偵測，再檢查產生的規則是否符合自己的命名方式。

智慧偵測的結果是方便修改的建議，並非保證適用所有命名格式；請務必透過預覽確認。

#### 5-3. 搜尋選項

批次修改提供以下選項：

| 選項 | 說明 |
|---|---|
| 區分大小寫 | 開啟後，搜尋時會區分英文字母大小寫。例如 `Face` 與 `face` 視為不同內容。 |
| 全字匹配 | 限制搜尋內容以完整字詞方式匹配，避免只修改較長名稱中的部分內容。 |
| 正規表示式 | 將搜尋內容作為正規表示式規則處理，可用於較複雜的名稱格式。 |

若不熟悉正規表示式，建議先使用一般搜尋與取代，或參考介面內提供的規則範例。

#### 5-4. 正規表示式範例與符號

介面提供常見命名情境範例，例如：

- `名稱_差分` → `@差分`
- `名稱＋數字＋底線` → `@`
- `角色（數字）` → `@`
- `角色／角色2_` → `@`

也提供可插入搜尋欄位的符號，例如 `{a}`、`{A}`、`{d}`、`{D}`、`{N}`、`{(N)}`、`{N_}`、`{w}`、`{W}`、`{s}`、`{S}`、`{.}`。這些是工具提供的正規表示式輔助代碼；實際匹配方式請以介面範例及預覽結果為準。

### 6. 位置與外觀

位置與外觀區可展開或收起，設定角色在 Room 中的擺放資訊及外觀。

| 欄位 | JSON 欄位 | 說明 |
|---|---|---|
| X 座標 | `x` | 角色在 Room 中的水平位置。 |
| Y 座標 | `y` | 角色在 Room 中的垂直位置。 |
| 旋轉角度 | `angle` | 角色圖片的旋轉角度。 |
| 寬度 | `width` | 角色圖片寬度。 |
| 高度 | `height` | 角色圖片高度。 |
| 顏色 | `color` | 角色顏色，可輸入 HEX 色碼。 |

#### 顏色設定

顏色欄位支援 HEX 格式，例如：

```text
#E0E0E0
```

欄位旁有顏色選擇器。你可以直接輸入色碼，也可以使用顏色選擇器挑選顏色；兩者會互相同步。

### 7. 顯示設定

顯示設定區提供角色狀態的勾選項目：

| 選項 | JSON 欄位 | 說明 |
|---|---|---|
| 啟用 | `active` | 角色的啟用狀態。 |
| 不公開角色狀態 | `secret` | 設定角色狀態是否不公開。 |
| 發言時不顯示角色立繪 | `invisible` | 發言時不顯示角色立繪。 |
| 不在盤面的角色清單中顯示 | `hideStatus` | 控制角色是否顯示於盤面角色清單。 |

請依照實際使用情境調整。這些選項與角色圖片、差分資料是不同的設定，不會因為修改圖片而自動變更。

### 8. 常用指令

常用指令欄位對應角色資料中的 `commands`，可放置 CCFOLIA 角色常用的檢定指令或其他常用文字。

例如：

```text
CC<=50 偵查
CC<=60 圖書館
CC<=40 心理學
```

工具會將欄位內容寫入角色 JSON。若你使用 Google 試算表同步，常用指令也會納入差異比對；部分基礎屬性檢定行則會依試算表指定儲存格同步，詳見[Google 試算表同步](#11-google-試算表同步)。

### 9. JSON 即時預覽與匯出

頁面下方的「最終 JSON」區會顯示目前表單產生的完整角色資料。當你修改表單欄位時，JSON 會同步更新。

提供以下操作：

- **複製 CCFOLIA JSON：** 將目前 JSON 複製到剪貼簿，方便貼到 CCFOLIA 或其他工具。
- **下載 JSON：** 將目前角色資料下載為 `.json` 檔案。
- **下載 CCFOLIA Room ZIP：** 將角色資料與圖片打包成 Room ZIP，詳見下一節。
- **全部清空：** 清除目前編輯中的資料，重新建立角色。

> 使用「全部清空」前，請先確認已經複製或下載需要保留的資料。清空後若沒有備份，便需要重新匯入或建立。

### 10. 匯入角色 JSON

按下頁面上方的「匯入 JSON」即可開啟匯入視窗。將 JSON 貼入欄位後，按下「匯入」載入資料；按下「清空」可清除匯入欄位內容。

#### 支援的輸入形式

**一般 CCFOLIA Character JSON：**

```json
{
  "kind": "character",
  "data": {
    "name": "角色名稱"
  }
}
```

**整份 JSON 被包成字串：**

```text
"{\"kind\":\"character\",\"data\":{...}}"
```

**Excel／CSV 常見的雙引號跳脫格式：**

```text
"{""kind"":""character"",""data"":{...}}"
```

工具會嘗試整理常見的字串包裝及引號格式，再解析角色資料。匯入後可載入的內容包含名稱、行動值、變動屬性、固定屬性、常用指令、備註、圖片資料、位置、顯示設定及差分資料等。

若資料無法解析，請先確認複製內容是否完整、是否為角色 JSON，以及外層 JSON 結構是否正確。

### 11. Google 試算表同步

本工具可以讀取 Google 試算表中的 CCFOLIA 角色 JSON，並在資料有變更時顯示差異比對視窗，讓你選擇要套用的項目。

#### 11-1. 使用前準備

1. 將 CCFOLIA 角色 JSON 放入 Google 試算表。
2. 確認角色資料位於預設的「人物卡」工作表分頁。
3. 將試算表設定為工具可以讀取的共用權限。若試算表需要登入授權才能讀取，工具可能無法取得資料。
4. 複製 Google 試算表的共用連結。
5. 回到工具，在「外部連結」欄位貼上試算表連結。

工具會從網址中辨識試算表 ID，並透過 Google 試算表的公開查詢輸出讀取資料。請勿將私人或不應公開的敏感資料放入可公開讀取的試算表。

#### 11-2. 試算表資料格式

工具會在「人物卡」分頁中尋找 CCFOLIA Character JSON。資料可以是單一儲存格內的完整 JSON，也會嘗試從相鄰儲存格組合內容中辨識角色 JSON。

基本形式如下：

```json
{
  "kind": "character",
  "data": {
    "name": "角色名稱",
    "status": [],
    "params": [],
    "commands": ""
  }
}
```

若分頁中找不到可辨識的完整角色 JSON，工具會提示無法找到角色資料。

#### 11-3. 自動檢查更新

貼上或輸入試算表連結後，工具會排程讀取資料。當連結已經存在於欄位中時，重新開啟工具也會嘗試檢查一次。

同步機制包含：

- 輸入連結後會延遲一小段時間再執行檢查，避免每輸入一個字就送出請求。
- 正常輪詢間隔約為 **30 秒**。
- 單次讀取逾時時間約為 **15 秒**。
- 若試算表內容沒有變更，不會一直重複顯示相同的更新提示。
- 匯入角色 JSON 或 Room ZIP 後，也會安排檢查，確認匯入資料與連結中的試算表是否有差異。

請注意，這是由工具定期讀取試算表的同步方式，不代表 Google 試算表會主動推送更新。

#### 11-4. 差異比對視窗

當工具偵測到試算表內容與目前角色資料不同時，會開啟「Google 試算表差異比對」視窗。

比對內容可能包含：

- 角色名稱及其他一般欄位。
- 變動屬性與固定屬性。
- 常用對話表／指令內容。
- 新增、刪除或修改的資料列。
- 其他可比較的角色資料欄位。

常用指令會進行較細緻的文字差異呈現，方便查看哪些指令行有變動。一般欄位也會顯示修改前後的內容。

視窗提供以下操作：

| 操作 | 說明 |
|---|---|
| 全選可更新項目 | 勾選所有可套用的差異項目。 |
| 全部取消 | 取消目前已勾選的差異項目。 |
| 只顯示被修改內容 | 篩選顯示有變更的內容，減少檢視未修改項目的干擾。 |
| 取消，不更新 | 放棄本次更新，維持目前角色資料。 |
| 套用勾選項目 | 只套用已勾選的差異項目。 |

建議先使用「只顯示被修改內容」檢視差異，再依需求勾選要更新的項目。若不希望更新某些資料，取消該項目的勾選即可。

#### 11-5. 本機優先保留的資料

為避免同步試算表時覆蓋本機圖片及外觀設定，下列欄位以目前本機資料為準，不會由試算表差異更新覆蓋：

- 主圖片 `iconUrl`
- 差分資料 `faces`（包含差分名稱與圖片關聯）
- 角色顏色 `color`
- 啟用狀態 `active`
- 不公開狀態 `secret`
- 發言時隱藏立繪 `invisible`
- 隱藏角色清單狀態 `hideStatus`

因此，試算表同步主要用於更新角色文字、數值、屬性及指令資料；圖片與上述顯示設定仍由目前工具中的本機資料保留。

#### 11-6. 基礎屬性數值同步

工具另外會從試算表指定儲存格讀取基礎屬性，並同步到角色常用指令中的對應檢定行。這些儲存格位置依目前程式設定，並非任意位置：

| 屬性 | 試算表位置 |
|---|---|
| 力量 | `S6` |
| 敏捷 | `S7` |
| 意志 | `S8` |
| 體質 | `S9` |
| 外貌 | `S10` |
| 教育 | `S11`，之後由 `Y10` 的「知識」最終值覆蓋 |
| 體型 | `S12` |
| 智力 | `S13`，之後由 `Y9` 的「靈感」數值覆蓋 |
| 幸運 | `Q14` |
| 靈感 | `Y9` |
| 知識 | `Y10`（作為教育檢定值） |

其中智力會以 `Y9` 的靈感數值覆寫對應的智力檢定行；教育會以 `Y10` 的知識最終值覆寫對應的教育檢定行；幸運會更新角色 `status` 中名稱為「幸運」的項目（若該項目存在）。若試算表的版面或儲存格位置與預期不同，讀取結果可能不正確。

#### 11-7. 同步時的建議

- 第一次使用前，先備份目前角色 JSON。
- 確認試算表分頁名稱為「人物卡」。
- 確認共用權限允許工具讀取。
- 先檢查差異內容，再套用更新。
- 若圖片或顯示設定是以本機為準，請直接在工具中修改，不要期待試算表覆蓋這些欄位。
- 若基礎屬性讀取不正確，優先檢查試算表指定儲存格是否與上表一致。

### 12. CCFOLIA Room ZIP

除了單獨匯出角色 JSON，也可以將角色資料與圖片一起打包成 CCFOLIA Room ZIP。

#### 12-1. 建立 Room ZIP

完成角色資料及圖片設定後，按下「下載 CCFOLIA Room ZIP」。工具會建立 ZIP 檔案，檔名通常會使用角色名稱，格式如下：

```text
<角色名稱>-ccfolia-room.zip
```

ZIP 主要包含：

```text
__data.json
.token
<圖片 SHA-256>.png
<差分圖片 SHA-256>.png
...
```

- `__data.json`：Room 資料及角色資料。
- `.token`：依照 `__data.json` 的 SHA-256 雜湊值建立的識別內容。
- PNG 檔案：角色主圖片及差分圖片。

建立 ZIP 時，工具會整理 Room 所需資料結構，並將圖片以 SHA-256 作為檔名。同一張完全相同的圖片不需要在 ZIP 中重複加入。

#### 12-2. Room 資料內容

Room 資料會包含 CCFOLIA Room 所需的主要結構，例如：

```text
entities
├── room
├── items
├── decks
├── notes
└── characters

effects
scenes
savedatas
snapshots
resources
```

角色資料除了基本角色欄位，也會包含 Room 使用的相關欄位，例如玩家名稱、位置、顏色、Room ID、Speaking、Dice Skin 等。

#### 12-3. ZIP 建立前的驗證

建立 Room ZIP 時，工具會檢查及整理相關資料，包括：

- 主圖片的 SHA-256。
- 角色 `iconUrl` 與主圖片檔名的對應。
- Room `resources` 中的圖片資源。
- Room JSON 中的角色資料。
- `.token` 與 `__data.json` 的雜湊對應。

這些處理是為了讓 ZIP 內的資料與圖片引用保持一致。

#### 12-4. 匯入 Room ZIP

若要重新載入 Room ZIP，請使用頁面上方的「匯入 ZIP」：

1. 選取 CCFOLIA Room ZIP 檔案。
2. 工具會讀取 ZIP 內的 `__data.json`、`.token` 及圖片檔案。
3. 從 Room 的 `entities.characters` 中取得角色資料。
4. 重新載入角色主圖片與差分圖片。
5. 檢查圖片預覽、差分名稱及其他角色欄位。

請區分「匯入 ZIP」與差分區內的「匯入 ZIP」：前者用來匯入完整 Room，後者用來匯入差分圖片資料。

## 四、建議使用流程

### 情境 A：從零建立一張角色卡

1. 填寫基本資料。
2. 建立變動屬性，例如 HP、SAN。
3. 建立固定屬性，例如 DB。
4. 選擇主圖片。
5. 新增差分並逐筆選擇 PNG。
6. 若差分名稱有共同規則，使用批次修改功能整理名稱。
7. 設定位置、尺寸、顏色及顯示狀態。
8. 填入常用指令。
9. 檢查最終 JSON。
10. 下載 JSON 或建立 Room ZIP。

### 情境 B：修改既有角色卡

1. 先備份原始 JSON 或 Room ZIP。
2. 匯入角色 JSON，或匯入 Room ZIP。
3. 檢查圖片是否正確載入。
4. 修改需要調整的欄位。
5. 確認 JSON 預覽。
6. 重新匯出。

### 情境 C：大量整理差分名稱

1. 先匯入既有角色或差分圖片。
2. 確認所有差分都已載入。
3. 開啟「修改名稱」。
4. 使用智慧偵測或自行輸入搜尋／取代規則。
5. 視需要設定大小寫、全字匹配及正規表示式。
6. 按下「預覽」，逐筆檢查修改結果。
7. 確認無誤後按「儲存」。
8. 檢查差分清單，再匯出角色資料。

### 情境 D：使用 Google 試算表管理角色資料

1. 在試算表中準備符合格式的角色 JSON。
2. 確認分頁名稱及讀取權限。
3. 將試算表連結貼到角色的外部連結欄位。
4. 等待工具讀取並比對資料。
5. 在差異視窗中確認新增、修改及刪除項目。
6. 只勾選希望更新的欄位。
7. 套用更新後，檢查角色資料及常用指令。
8. 視需要下載 JSON 或 Room ZIP 備份。

## 五、資料格式與圖片處理說明

### 1. Character JSON 基本結構

工具產生的角色 JSON 使用 CCFOLIA Character 格式，外層結構如下：

```json
{
  "kind": "character",
  "data": {
    "name": "角色名稱",
    "memo": "",
    "initiative": 0,
    "status": [],
    "params": [],
    "commands": ""
  }
}
```

常見欄位對照：

| JSON 欄位 | 用途 |
|---|---|
| `name` | 角色名稱 |
| `memo` | 備註 |
| `initiative` | 行動值 |
| `externalUrl` | 外部連結 |
| `status` | 變動屬性 |
| `params` | 固定屬性 |
| `iconUrl` | 角色主圖片 |
| `faces` | 差分圖片資料 |
| `x`、`y` | 位置座標 |
| `angle` | 旋轉角度 |
| `width`、`height` | 圖片尺寸 |
| `color` | 角色顏色 |
| `active` | 啟用狀態 |
| `secret` | 不公開角色狀態 |
| `invisible` | 發言時隱藏角色立繪 |
| `hideStatus` | 不在盤面角色清單顯示 |
| `commands` | 常用指令 |
| `owner` | Owner |

### 2. PNG 與 SHA-256 命名

主圖片及差分圖片使用 PNG。工具會讀取圖片原始資料並計算 SHA-256，Room ZIP 中的圖片檔名會使用該雜湊值：

```text
原始圖片：character.png
ZIP 圖片：<SHA-256>.png
```

主圖片會依原始 PNG bytes 計算 SHA-256；差分圖片也採用相同的雜湊命名方式。

如果多個差分使用完全相同的圖片內容，建立 ZIP 時會避免重複加入相同圖片檔案。

### 3. Room ZIP 與一般 JSON 的差異

| 格式 | 內容 | 適合用途 |
|---|---|---|
| Character JSON | 單一角色資料 | 傳送、備份或在其他地方編輯角色資料。 |
| Room ZIP | Room 資料、角色資料、圖片資源及驗證資訊 | 將角色與相關 Room 資料、圖片一起打包。 |
| 差分 ZIP | 差分圖片清單及圖片資料 | 匯入一組差分圖片。 |

三者用途不同，匯入時請選擇對應的入口。

## 六、常見問題與排除方式

### Q1：匯入 JSON 後沒有正確顯示資料？

請確認：

- 貼上的內容是否完整，沒有漏掉開頭或結尾。
- 內容是否為 CCFOLIA 角色 JSON，而不是 Room ZIP 內的 `__data.json`。
- JSON 是否有正確的 `kind: "character"` 及 `data` 結構。
- 若來源是 Excel／CSV，複製內容是否帶有額外引號或跳脫字元。

工具會嘗試處理常見的字串包裝格式，但無法保證修復所有不完整或錯誤的 JSON。

### Q2：圖片無法載入？

請確認：

- 主圖片及差分圖片是否為 PNG。
- 選取的檔案是否有效且沒有損毀。
- 匯入 ZIP 是否包含對應的圖片檔案。
- 若使用差分 ZIP，是否包含工具需要的 `sprite-namer.json` 清單。

### Q3：選取圖片後，差分名稱不符合預期？

可以先檢查設定選單中的「自動帶入圖片名稱」是否開啟。若名稱已經填入但需要統一修改，可使用「修改名稱」進行批次處理，並先預覽再儲存。

### Q4：批次修改後名稱不對，可以復原嗎？

批次修改視窗在儲存前可使用「取消」放棄變更。若已經儲存，請依照原始名稱重新執行取代，或重新匯入修改前的備份。建議大量修改前先複製差分名稱或備份角色 JSON。

### Q5：Google 試算表無法同步？

請依序檢查：

1. 外部連結是否為有效的 Google 試算表網址。
2. 試算表是否允許工具讀取；需要登入才能存取的私人文件可能無法讀取。
3. 分頁名稱是否為「人物卡」。
4. 分頁中是否包含可辨識的完整 CCFOLIA Character JSON。
5. 網路是否正常，是否遇到 Google 試算表服務暫時無法回應。
6. 若是基礎屬性錯誤，請確認指定儲存格位置是否與[基礎屬性數值同步](#11-7-基礎屬性數值同步)相符。

### Q6：為什麼試算表更新後，圖片或顯示設定沒有跟著改？

這是預期行為。為了保留本機圖片及外觀設定，主圖片、差分、角色顏色及部分顯示勾選欄位會以本機資料為準，不接受試算表覆蓋。

### Q7：差異比對視窗為什麼沒有自動更新所有內容？

同步採用選擇性更新。工具會列出可比較的差異，使用者需要勾選要套用的項目，再按下「套用勾選項目」。沒有勾選的項目會保留目前資料；按下「取消，不更新」則會放棄本次更新。

### Q8：Room ZIP 匯入與差分 ZIP 匯入有什麼不同？

Room ZIP 匯入會讀取完整 Room 資料及角色；差分 ZIP 匯入只處理差分圖片清單與圖片。請依照 ZIP 的來源及用途選擇對應按鈕。

### Q9：下載的 ZIP 裡面為什麼看不到原始圖片名稱？

Room ZIP 會使用圖片 SHA-256 作為檔名，以便讓圖片引用及資源內容保持一致。因此 ZIP 內看到雜湊字串作為檔名是正常現象。

### Q10：主題或設定更換後，重新開啟還會保留嗎？

主題及部分介面設定會儲存在目前瀏覽器的本機儲存空間。同一瀏覽器、同一網站環境下通常會沿用設定；清除網站資料、使用無痕模式或更換瀏覽器後，設定可能不會保留。
